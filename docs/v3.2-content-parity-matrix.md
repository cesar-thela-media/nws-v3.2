## Mission and source rules

The goal of v3.2 is to apply the current client site's complete meaningful content and copy to the local v3.1 visual design and technical foundation.

```text
www.nws-homes.com = factual content, copy, URL, and asset source
local v3.1         = visual design, components, architecture, and deployment source
v3.2               = v3.1 presentation with complete verified client content parity
```

This document records differences and required actions. It does **not** claim parity and does not authorize implementation of unresolved decisions.

## Classification legend

- **Exact:** Local source substantially matches the captured client content and fact.
- **Faithful restructuring:** The same meaningful content/intent is present in a different v3.1 layout or component structure; browser verification is still required.
- **Differing / needs review:** Meaningful copy, metadata, headings, counts, CTA, or structure differs and requires deliberate correction or acceptance.
- **Missing:** Captured client content has no local equivalent or is omitted from the shipped render.
- **Unsupported local addition:** Local content or claim is not evidenced by the captured client source and requires removal or explicit approval.
- **Wrong link/fact:** A URL, destination, phone, claim, or other factual value conflicts with the source.
- **Asset mismatch:** An image, icon, logo, alt text, or meaningful visual asset differs, is absent, or is semantically questionable.
- **Decision required:** The source contains an ambiguity/anomaly or v3.1 makes an intentional departure that must be resolved before implementation.
